Clarity

Vague buttons like “Submit”, jargon, error codes, passive voice, double negatives and messages that don’t say how to fix the problem.

Accessibility

“Click here” links, colour-only or position-only instructions, ALL CAPS, emoji, symbol-only text and user-blaming wording.

Flesch reading scores, plus a cross-check of terms, capitalisation and punctuation, so “Log in” isn’t “Sign in” on the next screen.

How it works

1. Scan. The server downloads the page’s HTML (blocking private networks) and parses it to extract buttons, links, form labels and placeholders, headings, error or alert messages, image descriptions and paragraphs. It also records page-level problems such as images without alt text, form fields without labels, missing page language and disabled zoom.

2. Analyse. The reviewer is a rule-based NLP engine, so it runs offline with no model downloads. Each string is tokenised into words and sentences, then checked against lexicons and patterns for each dimension.

Clarity uses word lists (jargon, vague actions, abbreviations), regular-expression patterns for passive voice, negatives and error codes, and length limits per element type. Accessibility rules follow WCAG ideas such as Sensory Characteristics and descriptive link text.

Reading level uses the Flesch Reading Ease and Flesch-Kincaid Grade formulas with a built-in syllable counter. Consistency compares all strings together to catch term variants, mixed capitalisation and mixed punctuation.

3. Recommend. Every issue comes with a suggestion, many strings get an automatic rewrite, and the whole report can be exported.

This is guidance to support — not replace — human and assistive-technology testing.
